# 과제 05 - 순차 탐색과 이진 탐색 트리 탐색의 비교
## 1. 실험 개요

본 프로그램에서는 0부터 1,000 사이의 정수 100개를 임의로 생성하고,
생성된 데이터를 정수 배열과 이진 탐색 트리(BST)에 저장하였다.

배열에서는 순차 탐색(Sequential Search)을 수행하고,
BST에서는 BST 탐색을 수행하였다.

총 50개의 탐색 키를 사용하여 두 탐색 방법의 숫자 비교 횟수를 측정하였다.

또한 BST를 생성하는 과정에서 발생하는 비교 횟수도 측정하여,
BST 생성 비용을 포함한 전체 성능을 비교하였다.

## 2. 실험 결과

### 데이터

- 데이터 개수: 100
- 탐색 횟수: 50

### BST 생성

- BST 생성 비교 횟수: 615회

### 순차 탐색

- 총 비교 횟수: 4812회
- 평균 비교 횟수: 96.24회

### BST 탐색

- 총 비교 횟수: 429회
- 평균 비교 횟수: 8.58회

### BST 전체 비용

- BST 생성 비용: 615회
- BST 탐색 비용: 429회
- 전체 비용: 615 + 429 = 1044회

## 3. 순차 탐색 분석

순차 탐색은 배열의 첫 번째 원소부터 시작하여 탐색 키와 하나씩 비교한다.

이번 실험에서 순차 탐색의 총 비교 횟수는 4812회이고,
평균 비교 횟수는 96.24회였다.

탐색 키가 배열에 존재하지 않는 경우에는 배열의 모든 100개 원소를
확인해야 하므로 100회의 비교가 발생하였다.

또한 탐색 키가 배열의 앞쪽에 존재하면 비교 횟수가 적어지고,
뒤쪽에 존재하면 비교 횟수가 많아지는 것을 확인할 수 있었다.

따라서 순차 탐색은 데이터의 위치에 따라 비교 횟수가 달라지며,
데이터가 많아질수록 탐색 비용이 증가할 수 있다.

## 4. BST 탐색 분석

BST 탐색은 현재 노드의 값과 탐색 키를 비교한 후,
탐색 키가 작으면 왼쪽 서브트리로 이동하고,
크면 오른쪽 서브트리로 이동한다.

이번 실험에서 BST 탐색의 총 비교 횟수는 429회이고,
평균 비교 횟수는 8.58회였다.

순차 탐색의 평균 비교 횟수인 96.24회와 비교하면,
이번 실험에서는 BST 탐색이 더 적은 비교 횟수로 탐색을 수행하였다.

이는 BST의 정렬된 구조를 이용하여 탐색할 필요가 없는
부분을 제외할 수 있기 때문이다.
## 5. BST 생성 비용을 고려한 분석

BST 탐색은 탐색 과정에서 적은 비교 횟수를 사용할 수 있지만,
탐색을 수행하기 전에 BST를 생성해야 한다.

이번 실험에서는 BST를 생성하는 과정에서 총 615회의 비교가 발생하였다.

BST 탐색에 사용된 비교 횟수는 429회이므로,
BST 생성 비용까지 포함한 전체 비교 횟수는 다음과 같다.

615 + 429 = 1044회

반면 순차 탐색에서는 별도의 탐색 구조를 생성할 필요가 없으며,
50회의 탐색에서 총 4812회의 비교가 발생하였다.

이번 실험에서는 BST 생성 비용을 포함하더라도
BST의 전체 비교 횟수는 1044회로,
순차 탐색의 4812회보다 적었다.

BST 생성에는 삽입 1회당 평균 6.15회(615/100)의 비교가 발생하였으며,
이는 균형 트리의 깊이(약 log2(100) ≈ 6.6)와 비슷하다.
BST는 탐색 1회당 약 87.66회(96.24-8.58)를 절약하므로,
생성 비용 615회를 회수하려면 약 7회 이상 탐색해야 한다.
이번 실험은 50회 탐색이므로 BST가 유리하였다.
## 6. 탐색 성능 차이에 대한 분석

순차 탐색은 배열의 처음부터 끝까지 순서대로 확인하기 때문에
탐색 키를 찾을 때까지 많은 원소를 비교할 수 있다.

반면 BST는 각 노드의 값을 기준으로 왼쪽 또는 오른쪽 서브트리 중
하나를 선택하여 탐색 범위를 줄인다.

이번 실험에서는 순차 탐색의 평균 비교 횟수가 96.24회였지만,
BST 탐색의 평균 비교 횟수는 8.58회였다.

따라서 이번 실험에서는 BST가 순차 탐색보다 적은 비교 횟수로
탐색을 수행하였다.
## 7. BST 구조에 따른 탐색 성능 변화

BST의 탐색 성능은 트리의 구조에 따라 달라질 수 있다.

BST가 균형에 가깝게 구성되면 각 단계에서 탐색할 범위를
효율적으로 줄일 수 있기 때문에 탐색 비교 횟수가 적어진다.

반면 데이터가 특정한 순서로 삽입되어 한쪽 방향으로 치우친
트리가 만들어지면 트리의 높이가 커진다.

예를 들어 데이터가 작은 값부터 큰 값 순서로 삽입되면
BST가 한쪽으로 길게 연결된 형태가 될 수 있다.

이 경우 BST 탐색의 성능이 저하되어 최악의 경우
순차 탐색과 비슷하게 많은 비교가 필요할 수 있다.

따라서 BST의 탐색 성능은 단순히 데이터의 개수뿐만 아니라
트리의 구조와 데이터가 삽입되는 순서에도 영향을 받는다.

이번 실험에서는 난수를 삽입하여 트리가 균형에 가까웠고,
그 결과 평균 탐색 비교 횟수가 8.58회로 낮았다.
반대로 데이터가 정렬된 순서로 삽입되면 트리가 한쪽으로 길게
연결되어, 생성에 0+1+...+99 = 4,950회의 비교가 필요하고
탐색도 순차 탐색처럼 최대 100회가 필요하다.

## 8. 결론

이번 실험에서는 100개의 데이터를 사용하여
순차 탐색과 BST 탐색의 비교 횟수를 측정하였다.

순차 탐색은 총 4812회, 평균 96.24회의 비교가 발생하였고,
BST 탐색은 총 429회, 평균 8.58회의 비교가 발생하였다.

BST 생성 과정에서는 615회의 비교가 발생하였으며,
이를 BST 탐색 비용과 합하면 전체 1044회의 비교가 발생하였다.

이번 실험 결과에서는 BST 생성 비용을 포함하더라도
순차 탐색보다 적은 비교 횟수로 50회의 탐색을 수행할 수 있었다.

그러나 BST의 성능은 트리의 구조에 따라 달라질 수 있으며,
한쪽으로 치우친 트리가 생성되면 탐색 성능이 저하될 수 있다.
